# Backlog

Open read-side product and process ideas for Mimir Lite. An entry here does not imply approval, implementation, or priority beyond the state shown. Before proposing work on an entry, check it against the current references and the [discarded ideas](discarded.md); an entry is not authorization.

## Open ideas

| Idea | State | Scope and next decision |
|---|---|---|
| Attribute-use relations in the SQLite index | Open; five slices done, priority reduced | Precise attribute-use relations for meaningful `who-uses(Attribute)` and impact exploration; do not represent them as a regression-prevention gate. First slice done: `workwith_references_attribute` from WorkWithForWeb grids, orders, view tabs, fixedData, description attributes, and filter attributes (extractor 13). Second slice done: attribute names in WorkWithForWeb filter conditions (extractor 14). Third slice done: `code_references_attribute` from the code Parts of Procedure (Source, Rules), WebPanel and Transaction (Rules, Events), and DataProvider (Source, Rules) (extractor 15): reads, and the write role for unambiguous assignment targets (inside `new`/`for each` blocks, Transaction assignment rules, Transaction-output DataProvider items). Fourth slice done: the write role for the attributes the Transaction rules `Default` and `Equal` (first argument) and `Serial` (first and second arguments) assign (extractor 17); `parm(in:Attribute)` stays a read. Fifth slice done: `workwith_references_attribute` from mobile WorkWith (Smart Devices) layouts, orders, search, break by, and filters (extractor 18; see the WorkWith for Smart Devices row). Reverse-relation coverage for an `Attribute` target lists those types as partly extracted (`partially_extracted_source_types`, with `extracted` and `missing`), or as unextracted on an index older than the extractor that read them, and the other consumer types as unextracted. Next: a public-export comparison of extractor 16 and 17. Deferred, each to be weighed for read-side value against extractor cost and an index rebuild: ambiguous assignment targets (top-level assignments in Events and Procedures, reported as reads), Procedure Layout and WebForm Parts (Conditions are read since extractor 21), Business Component members (`&bc.Attribute`), SDT-output DataProvider items, and code in a `<Source>` outside any `<Part>`. Attribute formulas are read since extractor 21 (role `Formula read`, modern `Formula` property and classic `Formula`). |
| Call-site fingerprints | Open; demand-gated | Add part/block and, where useful, approximate line/context to known object-reference results. Define useful precision and measure index-build/storage cost before changing the query contract. Implementation threshold: a recent real batch migration (10+ callers) whose cost came from reading each caller's XML by hand after `who-uses` named the objects, plus a closed decision on fingerprint granularity. |
| Focused full-text lookup | Open; design needed | Evaluate literal lookup for captions or selected SQL/HTML text not already represented by structured relations. Define indexed content, noise controls, and empirical value; this is not semantic discovery. |
| Semantic discovery | Open; unassessed | Explore whether intent-based search can help find candidate objects when names are unknown. First establish a real use case and compare with the existing SQLite/index workflows; do not select a framework or vector store in advance. |
| Deterministic relationship diagrams | Open; demand-gated | Consider opt-in, depth-one Mermaid diagrams from verified index/XML evidence, with explicit source and coverage. No inferred edges, whole-KB graph, LLM-authored graph, or external renderer in the initial concept. Reassess jointly with the index ideas above. Implementation threshold: two real documentation or triage requests in distinct KBs where the current text output is not enough to understand direct relations, or a concrete rework case caused by scattered relations; the first delivery would be a focal deterministic diagram with sanitized fixtures and asserts on nodes, edges, and coverage. |
| Generalization of empirical read-side findings | Open; evidence needed | Validate how far observed part-type semantics, parent/module naming, and XML patterns generalize across object families and independent GeneXus exports. Treat current findings as bounded evidence, not universal rules. |
| Additional representative read-side samples | Open; selective collection | Collect only when a concrete reading gap remains, prioritizing structurally dense Transaction families and contextual `Table`/`Index` evidence. Existing templates already cover many object types; there is no standing mandate to export one more sample of every type. |
| Open read-side distinctions | Open; reassess against current references | Recheck unresolved functional distinctions (for example, `Module` vs. `PackagedModule`) against current documentation and evidence. Close only with evidence. |
| Minimal default output for query scripts | Open; design needed | Evaluate a minimal-by-default result shape for the index query scripts and the index-triage output, with a structured `empty_reason` and a `suggested_next` hint when a result is empty, so a reader learns why nothing matched instead of guessing the next step. Decide the `empty_reason` vocabulary, the `suggested_next` form, and how a verbose opt-in coexists with the shell's native verbose switch. |
| Setup `doctor` and `whoami` | Open; design needed | Consider read-only companions to the existing setup audit: `doctor` (index freshness, skill registration across the agent tools in use) and `whoami` (which skills are active on this host, in which tool, and the source path of each installation). Start narrow and grow on demand; structured output by default. |
| Read-only KB identity drift audit | Open; design needed | Compare the stored KB identity metadata with the identity resolved from the local native KB now, to catch a stale GUID, metadata copied from another KB workspace, or an outdated username/UNC path that a syntactic check accepts. The audit only reports; it never rewrites metadata. |
| `SmartDevicesApplication` `queryableByKbIntelligence` reclassification | Open; evidence needed | Measure incoming/outgoing graph edges for `SmartDevicesApplication` objects in a KB workspace that has them. If the graph is empty or useless, set the flag to `false` in [the type catalog](../../skills/mimir-lite/scripts/gx-object-type-catalog.json) (currently `true`) and align the documentation; otherwise keep it and record brief evidence. Trigger: a KB workspace with such objects materialized, or a report of misleading `who-uses`/`impact-basic` output. |
| Extractor version-12 residuals | Open; low priority | Three deliberately deferred follow-ups to the `idBasedOn` to Domain extraction: escaped XML forms of `idBasedOn` beyond the already-normalized `&#xA;`; unifying the module resolver with `resolve_custom_type_target`, the SDT item path, and `exo:`; and a declared limitation that homonymous Domains in different modules do not coexist in the current one-file-per-short-name model. Do not expand the schema for the homonym case without new evidence. |
| Extractor version-14 residuals | Done | Shipped in extractor 16, each with a synthetic test: a quoted `>` or `/>` inside a `<filter>` tag attribute no longer misaligns the filter body; the WorkWith condition-to-Procedure path reads every line of a multi-line condition; a `//` inside a string literal is no longer a comment there or in a `Source` line. Nested `<filter>` elements do not occur in the pattern instance, so reading only up to the first `</filter>` is kept and pinned by a test. The token history after a `//` comment is kept on purpose: a comment is whitespace, and resetting it would read the object after a `udp(`/`call(` opener as an attribute; tests pin it. |
| `%TEMP%` cleanup in index self-tests | Done | Shipped: the eight index self-tests under `tests/mimir-lite/` that left a GUID temp tree in the system temp folder now remove it in `try`/`finally` with recursive removal, like `Test-KbIntelligenceIdBasedOnDomainSelfTest.ps1`, also when an assertion fails. No product behavior changes. |

| Agent friction seen in end-to-end runs | Partly done | Shipped: of four minor frictions seen while an agent followed the README and the workflows, three are fixed. A hypothesis about the unlisted users of an attribute now points at pattern instances (`WorkWithForWeb`, `WorkWith`) and authored code objects, never at objects generated from them; the **find** workflow gets the local time only when a reply or record states a time; the **setup** workflow checks the exact global instruction files and never searches the whole user profile. `SKILL.md` also says to read the skill's own files with the agent tool's file-read tool, once per session. The **setup** workflow also offers a Claude Code read rule for the clone's `skills` folder (step 20a), so reading the skill's own workflow and reference files no longer needs a permission approval each time. An end-to-end run then showed that the agent reads the skill through its Claude Code skill link, which the clone-path rule does not cover, so step 20a also offers a read rule for each skill link under `~/.claude/skills`. End-to-end runs confirmed the read rules: a session opened in the KB workspace reads the skill's files with no approval. |
